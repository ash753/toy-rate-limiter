# Step 8. nGrinder 부하 테스트 및 한계 성능 측정 - 요구사항

## 1. 개요
처리율 제한 장치(Rate Limiter)가 고부하 상황에서 얼마나 안정적으로 동작하는지 nGrinder를 통해 검증한다. 특히 로컬 개발 환경(Docker Desktop)에서 시스템이 견딜 수 있는 최대 임계치(Peak TPS)를 파악하여 시스템의 성능 한계를 도출한다.

## 2. 테스트 목표
- **최대 부하 측정 (Stress Test)**: 로컬 환경에서 시스템(Rate Limiter + Redis)이 처리 가능한 최대 TPS(Transactions Per Second)를 측정한다.
- **리소스 병목 파악**: 고부하 상황에서 CPU, 메모리, 네트워크 중 어느 자원이 먼저 한계에 도달하는지 확인한다.
- **안정성 검증**: 처리율 제한 임계치를 매우 높게 설정했을 때, 다중 인스턴스 환경에서 Redis와의 통신이 병목 없이 이루어지는지 확인한다.

## 3. 환경 요구사항
- **인프라 구성**: Docker Desktop의 로컬 Kubernetes 환경에 전체 스택 배포.
- **관측 가능성**: Grafana 대시보드(JVM, Rate Limiter)를 통한 리소스 및 메트릭 모니터링.
- **설정 변경**: 한계 측정을 위해 Rate Limiter의 정책 제한 수치를 임시로 상향(예: 1,000,000 req/min)하여 애플리케이션 로직이 아닌 시스템 자원 한계에 도달하게 함.

## 4. 주요 검증 항목
1. **Peak TPS 측정**: 시스템이 붕괴되기 직전까지의 최대 처리량 확인.
2. **응답 시간(MTT) 변화**: 부하 증가에 따른 지연 시간(Latency)의 변화 곡선 분석.
3. **Saturation Point 파악**: TPS가 더 이상 늘지 않고 에러가 발생하거나 응답 시간이 급증하는 지점 확인.
